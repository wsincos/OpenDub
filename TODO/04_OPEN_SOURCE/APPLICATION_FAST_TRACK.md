# Application Fast Track

## Objective

Prepare a coherent seed-grant application around the smallest credible platform release: **P0-P3** in [IMPLEMENTATION_PLAN.md](../03_EXECUTION/IMPLEMENTATION_PLAN.md). Do not wait for P4 Replay or P5 Live unless their evidence gates have already passed.

## Five-Step Submission Sequence

### 1. Freeze the platform statement

- Use the official Chinese and English project names in [GRANT_AND_DEMO.md](GRANT_AND_DEMO.md).
- Use one consistent sentence: Atlas helps users understand, select, and prepare complete methods; Studio records authorized projects; Replay/Live are evidence-gated.
- Remove stale language that calls OpenDub only an Atlas or promises immediate generation by all methods.

### 2. Freeze factual evidence

- Confirm repository URL, current version, license, verification command results, and the three core methods.
- Recheck every “already implemented” statement against `docs/PROJECT_CURRENT_STATE.md` and `docs/grant/evidence-index.md`.
- Keep `已有案例用户` as `暂无` unless a written permission and public reference exist.
- Do not claim public checkpoint availability, a formal release tag, real A/B results, or Live inference without its records.

### 3. Prepare the visual proof

- Record the platform path: task -> catalog -> method interaction -> Evidence Room -> project preparation.
- Keep the content mode visible in each recorded view.
- Use self-created or explicitly authorized media only.
- Include the platform architecture illustration and GitHub repository overview in the submission materials.

### 4. Complete the form and review

- Project background: explain the fragmented research-to-use workflow and AIGC content-creation value.
- Main functions: Atlas, method selection, authorized project preparation, evidence, and conditional replay/live path.
- Innovation: complete-method catalog and visual selection workbench, not a fictional new hybrid model.
- Stage targets: P1-P3 mandatory; P4-P5 conditional.
- Have the project lead verify names, roles, contact details, budget, and all externally visible claims.

### 5. Freeze and submit

- Record release commit, document version, screen-recording version, and submission date.
- Run full checks and a final fact/rights review.
- Package the Word form, technical documentation, video or recording link, repository link, and evidence index using the requested naming convention.

## Allowed Wording

### May state as current

- interactive Task Explorer, three complete Concept Method Canvases, Evidence Room, evidence-gated comparison interface, local project/media/authorization foundation, source audit, documentation, and automated validation;
- Concept is an interactive explanation; it does not claim new audio generation;
- the platform is open-source, local-first, and built around authorized media/voice references.

### Must state as planned or conditional

- real output from HPMDubbing, StyleDubber, or EmoDubber inside OpenDub;
- public same-input comparison, Live execution, released `v0.1.0`, checkpoint redistribution, multilingual, agentic, multi-character, real-time, or hardware-compatibility claims.

## Submission Red Lines

- Do not call the three methods one unified OpenDub model.
- Do not publish or demonstrate an unconsented voice or copyrighted media without permission.
- Do not call a historical demo or Concept animation a Live result.
- Do not publish fake metrics, A/B ranking, or claims of universal method superiority.
- Do not leave project identity inconsistent across the form, repository, film, and README.
