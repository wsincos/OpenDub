# Truth, Review, and Delivery QA

## 事实矩阵

| 影片元素 | 可以使用的条件 | 禁止表达 |
|---|---|---|
| “情感可控” | 真实 Adapter 对情感参数有可测作用，且有运行报告 | 仅有论文标题、UI 原型或未实现的参数 |
| “视频感知” | 实际生成或预处理使用视频帧/口型/表情/场景 | 仅展示视频播放器但模型不读取视频 |
| “音色一致” | 有授权参考声音和真实 speaker metric | 把单一演示听感说成身份保证 |
| “时间同步” | 真实目标窗、时长计算和导出测试 | 用剪辑软件手工对齐后说是模型自动完成 |
| “开放源码” | 主仓库公开、许可证可见、功能文档可访问 | 只有静态介绍页或私有代码 |
| “HPMDubbing/StyleDubber 支持” | 对应 Adapter 实际安装、测试并出现在 Registry | 仅在能力图或 Roadmap 中出现 |
| 性能数字 | 来自本次录制机器和报告 | 用不同机器、不同输入或论文数字替代 |

## 录制前技术核验

- [ ] 主仓库、版本号和 LICENSE 可匿名访问。
- [ ] 演示项目可从零打开，不依赖隐藏缓存或人工文件替换。
- [ ] 每一个 UI 控件对当前模型真实有效。
- [ ] 模型能力面板与 `adapter.yaml` 一致。
- [ ] 候选 A/B 由同一项目、相同视频、相同文本和相同响度规则生成。
- [ ] 指标数值来自录制项目的报告，包含单位与状态。
- [ ] 最终 MP4 可从确认候选渲染而来。
- [ ] 运行清单中的模型、权重、种子、版本与影片文字一致。

## 剪辑初版审查

由技术负责人、非项目成员和声音审查者各看一遍。三人分别回答：

### 技术负责人

- 是否有任何当前未实现能力被展示为已完成？
- 模型、权重、指标、时间和版本是否真实？
- 研究基础与产品功能是否被明确区分？

### 非项目成员

- 前 15 秒是否能理解“视频配音不同于 TTS”？
- A/B 段落是否无需解释也能听到差异？
- 看完后是否知道 OpenDub 的实际操作路径？
- 哪个术语或画面不清楚？

### 声音审查者

- A/B 响度是否公平？
- 音乐是否干扰判断？
- 旁白、角色声和字幕是否同步？
- 是否有削波、爆破音、突然静音或相位问题？

任一阻断问题出现，回到对应镜头重录或重剪；不通过字幕解释掩盖。

## 视觉验收

- [ ] 1080p、笔记本屏幕和手机上文字均可读。
- [ ] 所有 UI 操作符合真实产品状态，没有后期伪造按钮反馈。
- [ ] 没有系统通知、隐私信息、缓存路径、密钥或未授权素材。
- [ ] 图形颜色与 OpenDub 产品 token 一致。
- [ ] 没有与项目无关的 AI 视觉装饰。
- [ ] 画面、波形、时间线和字幕不互相遮挡。
- [ ] 开场和 A/B 段落保留足够纯听觉空间。
- [ ] 片尾链接停留至少 4 秒。

## 发布后的回溯

发布版本、源工程、演示项目、权利登记、指标报告和校验和必须一起归档。之后产品功能改变时，先比较影片中的声称；若不再准确，更新视频或在发布页面显著说明版本差异。
