# Scope and Success Criteria

## `v0.1.0` 必须交付

### 项目与素材

- 创建、打开、保存和复制一个 OpenDub 项目。
- 导入 MP4、MOV、WebM 视频；导入 WAV、FLAC、MP3 参考音频。
- 导入或编辑 SRT、VTT 和 OpenDub JSON 台词。
- 使用 FFmpeg 提取音频、探测媒体参数、切分片段并回填生成音轨。
- 保存素材哈希、时长、采样率、分辨率和来源说明。

### 配音创作

- 每个台词片段包含开始时间、结束时间、文本、角色、参考音频、情感类别、情感强度和模型配置。
- 支持逐片段生成、失败重试、候选保留、A/B 试听和候选确认。
- 首个稳定后端采用团队现有成熟代码中最先通过适配验收的一项；默认实现顺序为 EmoDubber，然后是 HPMDubbing。
- 支持目标时长约束，记录生成音频与目标时间窗的偏差。
- 将确认后的片段拼接为配音轨，并与原视频混流导出 MP4。

### 评测与可追溯

- 至少输出内容可懂度、说话人相似度、情感一致性和时长偏差四类指标。
- 每次生成保存模型 ID、适配器版本、权重 SHA-256、随机种子、设备、精度、运行时长和参数。
- 生成可机器读取的 `result.json` 与可阅读的 HTML/Markdown 报告。

### 使用入口

- `opendub doctor`：检查 FFmpeg、GPU、驱动、模型缓存和适配器。
- `opendub init`：创建项目。
- `opendub analyze`：分析视频和台词。
- `opendub generate`：生成片段或整项目。
- `opendub evaluate`：计算指标。
- `opendub render`：导出成片。
- 本地 Web Studio：项目列表、素材导入、时间线、片段检查器、任务状态、试听、评测和导出。
- REST API 与 Server-Sent Events 任务进度流。

### 开源交付

- Apache-2.0 平台许可证、第三方许可证清单、模型卡、数据与声音授权说明。
- 中英文 README、快速开始、架构说明、适配器教程、故障排查和贡献指南。
- Docker GPU 运行方式和原生 `uv` 安装方式。
- 两套可合法分发的短视频示例与完整演示录屏。
- GitHub Actions 完成格式、静态检查、单元测试、Web 测试、文档链接检查和容器构建。

## `v0.1.0` 明确不包含

- 自动翻译、自动改写台词和端到端多语言翻译。
- 多说话人自动聚类与身份识别。
- 实时配音和直播推理。
- 浏览器端神经模型推理。
- 多用户权限、计费、云存储和远程协作。
- Windows 与 macOS GPU 的正式支持。
- 对昇腾、寒武纪、海光等国产硬件的未验证承诺。
- 对长电影的一次性全自动处理；首版采用片段化工作流。

## 输入与规模边界

- 单项目视频建议不超过 10 分钟。
- 单台词片段支持 1 至 15 秒，超出范围时 UI 给出分段提示。
- 输入视频最高按 1920×1080、60 FPS 验证；更高规格允许导入但先生成代理文件。
- 参考声音建议 3 至 15 秒，必须包含单一、清晰说话人。
- 输出视频固定支持 H.264 + AAC MP4；原始 WAV 配音轨始终保留。
- 首版模型语言能力以所选后端真实支持范围为准，产品界面不得将“界面双语”表述为“配音多语言”。

## 质量指标

### 可用性

- 使用提供的 Docker 镜像和已缓存权重，快速开始到生成第一个示例的人工操作时间不超过 20 分钟。
- Web Studio 中完成“导入—编辑—生成—试听—导出”的主路径不超过 5 个阶段。
- 每个失败任务展示可执行的恢复建议和日志路径。

### 正确性

- 项目清单 JSON Schema 校验通过率 100%。
- 同一输入、同一权重、同一种子、同一设备配置下重复运行的元数据一致。
- 媒体时间线的片段边界误差不超过 20 毫秒。
- 输出音轨长度与视频长度偏差不超过一个音频采样帧。

### 工程质量

- 核心领域、项目存储、媒体命令构建和模型注册表单元测试覆盖率不低于 85%。
- API、CLI 和端到端主路径均有集成测试。
- Stable 适配器必须通过真实权重烟雾测试；仅用模拟适配器通过不得标记为 Stable。
- `main` 分支不得存在已知 Critical/High 级依赖漏洞。

### 社区质量

- 首次公开发布包含至少 10 个标签清晰的初始 Issue。
- 贡献者能够仅阅读适配器教程实现一个最小测试适配器。
- 发布包包含可验证的模型来源、许可证、引用信息和校验和。

## 验收场景

项目只有在以下场景全部通过时才能发布 `v0.1.0`：

1. 新机器通过 Docker 启动本地服务，打开 Web Studio。
2. 导入授权示例视频、台词和参考音频，系统完成媒体分析。
3. 为两个片段设置不同情感与强度，提交生成任务。
4. 在 Web UI 中比较至少两个候选并确认一个结果。
5. 生成四类指标报告，查看模型与权重追溯信息。
6. 导出包含新音轨的 MP4 和独立 WAV。
7. 使用 CLI 对同一项目再次渲染，并得到结构一致的结果。
8. 删除项目时仅删除项目工作目录，不删除共享模型缓存。
