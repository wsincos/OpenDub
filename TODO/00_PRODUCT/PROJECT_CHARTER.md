# Project Charter

## 使命

让视频创作者、研究人员和开发者能够在合法授权的前提下，用统一的开源工作流生成与角色、情感和画面节奏一致的高质量配音，并能解释、比较和复现生成结果。

## 问题定义

现有开源视频配音项目通常存在四类断裂：

1. 论文代码以训练或离线评测为中心，普通用户难以完成从视频导入到成片导出的全过程。
2. 各模型对视频帧、口型、表情、文本、参考音频和配置文件的要求不一致，无法互换。
3. 评价通常分散在不同脚本中，用户无法同时判断内容正确性、音色一致性、情感一致性和时间同步性。
4. 视频、电影片段和声音涉及版权与人格权益，现有演示常缺乏明确的授权链和安全说明。

OpenDub 解决的是这些断裂，而不是再创造一个孤立的语音模型。

## 目标用户

### 主要用户：视频内容创作者

需要为短视频、动画、公开课、数字人或自有影视素材生成配音。希望通过可视化工作台完成台词编辑、参考声音选择、情感调整、候选试听和视频导出。

### 次要用户：配音与语音研究人员

需要在统一输入、统一输出和统一指标下复现、比较不同视频配音方法，并保留完整运行配置。

### 次要用户：开源开发者

希望接入新的配音模型、视觉特征提取器、声码器或评测器，而不修改整个应用。

## 产品承诺

OpenDub 对用户承诺四件事：

- **Scene-aware**：生成过程可以使用口型、人脸表情和场景上下文，而非只读文本。
- **Character-consistent**：参考声音与说话人身份作为显式输入，输出报告音色相似度。
- **Emotion-directed**：用户可以设置情感类别和强度，系统保存控制参数并评估结果。
- **Timeline-ready**：每个配音片段有目标时间窗，生成结果可直接回填视频并导出。

## 产品边界

OpenDub 是：

- 本地优先的开源视频配音工作台；
- 面向模型适配和端到端推理的工具链；
- 可视化界面、REST API、Python API 和 CLI 的统一产品；
- 支持研究复现和创作使用的可追踪流水线。

OpenDub 不是：

- 在线商业 SaaS；
- 无授权声音克隆服务；
- 自动抓取或分发版权影视数据的平台；
- 首版即支持所有语言、所有模型、所有硬件的万能框架；
- 将多个原仓库直接复制到一个目录的代码集合。

## 核心产品叙事

普通 TTS 回答“这段文字应该怎么念”；OpenDub 回答“这个角色在这个画面、这个时间窗和这个情绪下，应该用怎样的声音说出这段台词”。

## 版本战略

### `v0.1.0`：可信闭环

完成项目工作台、媒体处理、授权参考音频、一个稳定配音后端、统一渲染、基础评测、CLI、API、Web UI、文档和演示。

### `v0.2.0`：能力扩展

接入 HPMDubbing 和 StyleDubber 适配器，完善视频韵律与风格控制，增加模型比较和批量候选生成。

### `v0.3.0`：研究前沿

在源代码、权重与许可可用的前提下接入 HD-Dub、CoSyncDiT 或 LLM-Flow-Dubber，并提供统一基准。

### `v1.0.0`：稳定生态

稳定插件 SDK、向后兼容的数据格式、完整模型注册表、可复现发布和至少两个外部贡献适配器。

## 成功形态

第一次接触 OpenDub 的开发者应在 20 分钟内完成安装并运行示例；创作者应在 5 个明确步骤内从合法示例素材生成成片；研究者应能够从结果清单中恢复模型、权重、参数、输入摘要和指标。
