# OpenDub V2 申报视频重制方案

## 1. 交付定义

| 项目 | 固定要求 |
| --- | --- |
| 版本 | `v2.0.0-showcase`，不覆盖 V1 MP4 |
| 时长 | 约 84.2 秒，30 FPS，1920x1080；录制母版可保留 4K |
| 主语言 | 字幕主导；中英双语字幕；同步中文人工旁白稿可作为后续录音版本 |
| 画面来源 | V2 Web 真实运行画面、经批准的案例视频、原创流程动画、现有证据页面 |
| 音频 | 非样例段为画面内明确标示的非语音说明音轨；样例段仅播放已批准的真实 GT 音轨；禁止用旁白冒充模型输出 |
| 交付物 | MP4、SRT、旁白文稿、镜头表、媒体 manifest、SHA-256、录制环境、事实检查表 |

## 3. 制作流程

1. 冻结批准的 asset manifest 和 V2 Web commit；录制时每个画面左下仅保留必要状态标签。
2. 以确定性的 Playwright 导览状态录制 `/vtts` 动画、线索切换和时间线拖动；使用 `scripts/capture_v2_web_clips.mjs`，禁用随机初始化、网络加载和鼠标抖动。
3. 单独录制两组 Example Gallery 片段。真实样例视频音量统一、同一时刻只播放一轨，并在片中明确 GT / 方法来源。
4. 用 Chrome / Playwright / FFmpeg 的可脚本化管线生成 1920x1080 30 FPS 镜头；不以静态网页截图代替动态数据流段。
5. 按镜头表合成画面内标明的非语音说明音轨、真实样例短音频和字幕。样例音频段落必须显示其 asset ID 和内容状态；后续人工旁白不得覆盖其关键可听部分。
6. 导出 MP4，嵌入字幕轨，保留独立 SRT，并由 `ffprobe` 检查时长、分辨率、帧率、音轨和字幕流。
7. 生成 SHA-256、`delivery-manifest.json`、`fact-check.md`。新的产物放在 `docs/grant/video/v2/`，V1 保留不动。

## 4. 录制与后期标准

- 前 22 秒必须是可读的真实浏览器交互录制：数据流、线索切换和时间线拖动均应可见；
- 每个案例镜头中方法名、GT 标签、内容状态和音频是否播放必须可见；
- 只能展示得到批准的真实样例声音；无批准时保留静音画面与字幕，不用合成音色替代；
- 允许少量剪辑节奏、胶片切换和非语音说明音轨，不添加会被误解为模型输出的“AI 合成音效”；
- 所有文字在 1920x1080 和 390x844 的截取镜头中保持可读；
- V2 应感觉像一个可操作的电影化研究工具，而不是演讲稿叠在网页截图上。
