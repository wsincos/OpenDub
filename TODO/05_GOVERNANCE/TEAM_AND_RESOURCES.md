# Team and Resource Plan

## 默认团队职责

申报表当前团队为李亮、丛高翔、王进禹。以下分工用于建立明确责任；正式提交前由负责人确认，但不会改变技术架构。

### 李亮：项目负责人

- 决定项目边界和申报承诺；
- 审核学术归属、许可与对外表述；
- 协调算力、场景和合作资源；
- 批准 Stable 模型和正式 Release；
- 对基金阶段成果负责。

### 丛高翔：模型与研究负责人

- 完成既有模型、权重和论文资产审计；
- 负责 EmoDubber、HPMDubbing、StyleDubber 等 Adapter 的技术正确性；
- 审核 HPMDubbing、StyleDubber、EmoDubber Method Canvas 的节点、边、信号和论文表述；
- 定义情感、风格、音色和同步评测；
- 提供可发布模型实现与授权示例；
- 审核模型卡和引用。

### 王进禹：平台与开源负责人

- 负责核心架构、Method Atlas、媒体管线、API、CLI 和 Web Studio；
- 建立测试、CI、Docker、Release 和文档；
- 维护项目 Schema、Adapter SDK 和任务追踪；
- 组织 Issue、PR、Demo 和社区反馈；
- 维护申报证据索引。

## 评审责任

| 变更 | 作者不得单独批准 | 必须批准人 |
|---|---|---|
| 模型 Adapter | Adapter 作者 | 模型负责人 + 平台负责人 |
| 项目 Schema/API | 实现作者 | 平台负责人 |
| 权重/数据许可 | 上传者 | 项目负责人 |
| 对外质量声明 | 文案作者 | 项目负责人 + 模型负责人 |
| Release | Release 执行者 | 项目负责人 |
| 安全修复 | 修复作者 | 至少另一名成员 |

三人团队不能要求两名以上互不相关维护者审批每个小改动；高风险事项使用上表，普通文档和内部重构由一名非作者检查即可。

## 节奏

- 每周一次 30 分钟 milestone 检查；
- 每个工作日异步更新“完成、下一步、阻断”；
- 每个任务一个 Issue 和一个可评审提交；
- M1/M2/M3 各做一次正式演示；
- 外部承诺只从已关闭 milestone 和验证报告生成。

最终支出以基金规则和财务要求为准，以下用于控制技术范围：

| 合计 | 12,000 元 | M1–M3 |

## 基础项目 4000 元缩减方案

| 类别 | 金额 | 对应产出 |
|---|---:|---|
| GPU 计算 | 2,200 元 | 一个 Stable Adapter 和基础指标 |
| 部署与存储 | 600 元 | Docker、模型清单、示例分发 |
| 文档与演示 | 700 元 | 快速开始、授权 Demo |
| 社区与机动 | 500 元 | Issue、用户验证、不可预见成本 |
| 合计 | 4,000 元 | M1、M2 核心和最小 M3 |

基础档必须缩减：

- 首版只接 EmoDubber 与必要声码器；
- HPMDubbing、StyleDubber 只保留 Adapter 设计和路线；
- 不做多硬件兼容；
- Web Studio 保留核心五阶段，不做复杂多轨和批量比较；
- 社区活动以一次公开演示为目标。

## 资源使用原则

- 不用基金购买无法形成公开产出的封闭服务；
- 计算支出关联具体 Adapter、指标或回归报告；
- 官方示例素材优先自制，避免版权采购不确定性；
- 所有可公开的代码、文档、配置和验证结果进入主仓库；
- 经费不足时先减少模型数量，不削弱许可、安全和真实测试。

## 公交因子

每个关键领域至少两人能够恢复：

- 模型：丛高翔主责，李亮掌握资产与许可；
- 平台：王进禹主责，丛高翔能够运行 Adapter；
- 发布与申报：王进禹执行，李亮持有最终归档与权限。

凭据不写入仓库。GitHub、模型存储和报名归档至少由负责人和执行者各自保有受控访问。
