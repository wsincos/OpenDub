## 一句话介绍

OpenDub 是面向 AIGC 视频内容生产的开源平台：它通过交互式可视化方法图谱，帮助创作者和开发者理解多模态视频配音任务、选择一个完整的配音方法、准备经过授权的本地输入、核查方法证据，并在证据满足时再进行结果回放、比较或本地运行。

## 项目背景与问题

视频配音并不是“文本输入后朗读出来”的普通 TTS。一个目标视频同时提供口型运动、人物表情、镜头情境和时间节奏；目标文本定义要表达的内容；经授权的参考语音提供可使用的角色身份或声音风格。因此，实际任务可概括为：

```text
Video + Target Text + Authorized Reference Speech
                    -> one complete dubbing method
                    -> Target Speech -> Dubbed Video
```

现有研究往往以论文、训练脚本和独立仓库的形式存在。不同工作具有不同输入特征、运行环境、权重条件和评测方式，创作者难以判断适用方法，开发者也难以在同一输入、同一权利条件下复现和比较结果。与此同时，视频、声音和角色身份还涉及著作权、肖像权和人格权益，不能把“可生成”直接等同于“可公开使用”。

## 项目方案

OpenDub 不把 HPMDubbing、StyleDubber、EmoDubber 的内部网络模块拼接成一个未经验证的新模型，也不把几个链接堆成一个模型目录。平台保留每项研究工作作为独立、完整的方法，并在它们之上构建统一的解释、选择、准备和证据层。

首版围绕三项团队研究基础组织交互式展示：

| 完整方法 | 解决的核心问题 | OpenDub 中的可视化功能 |
| --- | --- | --- |
| HPMDubbing | Lip、Face、Scene 等层级视觉线索如何约束语音韵律 | 分层视觉韵律图谱与可点击组件说明 |
| StyleDubber | 视频帧级、音素级、话语级表示如何共同刻画说话风格 | 多尺度风格对齐交互视图 |
| EmoDubber | 同步、清晰度、身份与情感控制如何共同参与视频配音 | 情感引导机制与控制条件说明 |

`HPMDubbing_Vocoder`、预处理和媒体工具被明确定位为支持性基础设施，不被写成第四个独立的视频配音方法。

## 当前已实现的主要功能

截至 `v0.0.1-alpha.0`，以下能力已有源代码和自动化测试支撑：

1. **任务解释与交互式方法图谱**：Task Explorer 清楚区分 `Target Speech` 与 `Dubbed Video`，三个完整 Method Canvas 可点击查看组件、信号、来源和限制。
2. **证据感知的方法选择**：Atlas 先以“视觉韵律与场景节奏 / 发音清晰度与角色风格 / 显式情感方向”给出可解释的首要需求导览，再引导用户检查或准备一个完整方法；平台写入方法 ID、固定 manifest/证据版本、输入要求、可选控制项、内容状态和运行状态，服务端拒绝不匹配或过期的选择记录。
3. **本地授权项目准备**：Studio 支持本地项目、内容寻址素材、整数微秒时间线、参考语音授权和片段配置；已选方法会显示在项目中，而非被当成可用的 Live 后端。
4. **可复现准备记录**：用户可为当前视频和目标文本记录授权声明；系统校验视频哈希、文本指纹、参考语音同意记录和片段方法一致性，导出版本化的 `opendub.project-preparation/v1` 清单。
5. **可信边界与开源基础**：三个方法的论文、固定源码提交、许可证、权重状态和运行状态在 Evidence Room 与审计文档中公开；平台代码采用 Apache-2.0，提供 REST API、CLI、Web 界面、测试、文档和本地优先的数据处理基础。

## 技术架构

平台采用“交互 Atlas + 本地 Studio + 证据门控”的模块化架构：

1. **Atlas 层**：以结构化 Method Manifest 描述完整方法、组件、输入、信号、来源与内容状态，驱动任务解释、方法选择和可视化交互。
2. **项目与授权层**：版本化 `project.json` 是项目真相源；素材按 SHA-256 内容寻址；视频、目标文本和参考语音分别保留授权/同意记录。
3. **准备导出层**：服务端重新计算输入哈希与文本指纹，生成原子写入的准备清单，便于后续由方法作者或通过准入的 Adapter 使用。
4. **模型准入层**：模型以固定上游 commit、许可证、权重条款、哈希、隔离运行环境和真实 smoke test 为准入条件；未通过前仅显示为 `Concept` 或 `planned`。
5. **条件执行层**：只有具备合格 Replay Bundle 时才展示同输入结果比较；只有完整方法通过准入时才允许本地 Live 推理。

平台工作流见 [架构图](../architecture/README.md)。该图刻画产品数据和证据流，不把多个研究方法误画为一个统一神经网络。

## 项目创新与开源贡献

1. **面向任务理解的交互式入口**：用可操作的 `Video + Text + Authorized Reference Speech` 任务视图，解释视频配音相对于普通 TTS 的视觉、时间和身份约束。
2. **完整方法而非模块拼装**：将已有研究贡献组织为可选择、可检视的完整方法，避免没有科学依据的跨论文模块混合。
3. **可视化与可交互的技术表达**：每个方法都以可点击的组件、信号和专属交互呈现其核心机制，降低论文代码对创作者、学生和外部开发者的使用门槛。
4. **授权与证据默认进入工作流**：将输入权利、内容哈希、方法证据版本和项目 revision 作为可导出记录，而不是事后补充说明。
5. **可扩展且不夸大的模型生态**：通过统一 manifest 和准入规则为新完整方法建立接入位置，同时严格区分 `Concept`、`Replay`、`Live` 与 `Planned`。

## 当前边界与阶段计划

当前版本**不声称** HPMDubbing、StyleDubber 或 EmoDubber 已在 OpenDub 中完成可公开的 Live 推理，也不展示来源不明的同输入 A/B/C 音频、模型指标或“最佳方法”排名。公开 checkpoint、论文网页 Demo 或源码仓库不能单独改变这一状态。

| 阶段 | 目标 | 验收边界 |
| --- | --- | --- |
| 已完成：P0-P2 | 任务解释、三方法图谱、证据核查、方法选择、本地授权项目和准备导出 | 无需模型权重即可完整演示 |
| 申报冻结：P3 | 架构图、统一文档/申报表、110 秒视频、质量验证和发布候选 | 每个画面和陈述可追溯到代码、测试或证据 |
| 条件升级：P4 | 授权的同输入 Replay 和公平比较 | 至少两份合格结果包及相同输入合同 |
| 条件升级：P5 | 首个完整方法的本地 Live 运行 | 源码、权重、权利、哈希、隔离运行、smoke test 和运行清单齐备 |

## 希望获得的孵化支持

1. 受控 GPU 算力和真实模型推理环境，用于完成首个完整方法和声码器的合规验证；
2. 模型权重、数据和声音授权的开源合规指导；
3. 公开课、数字人、短视频等明确授权场景的体验反馈；
4. 开发者社区传播、外部完整方法接入和国产算力验证资源。
