## 项目介绍

OpenDub 是一个本地优先、可追溯的视频配音开源工作台。它面向短视频、动画、数字人、公开课等自有或已授权内容，统一管理视频、台词、授权参考声音、目标时间窗、模型能力、候选音频和评测记录。与只依据文本生成语音的工具不同，OpenDub 将“角色在这个画面、这个时长和这个情绪下应如何说话”建模为可扩展的项目与时间线工作流。

项目不将多个论文仓库简单拼接为一个产品。HPMDubbing、StyleDubber、EmoDubber 与 HPMDubbing_Vocoder 是团队既有研究和开源技术基础；OpenDub 的本次建设目标是把这些研究方向逐步纳入统一的适配、运行、评测和展示框架。只有完成代码、权重、许可和真实推理验证的后端，才会在产品中声明为可用模型。

## 项目背景

视频配音同时受到文本语义、人物音色、口型与表情节奏、镜头情境和目标时长的约束。现有开源成果多以训练和离线评测脚本为中心：输入格式、特征提取、模型环境和评价标准彼此割裂，普通创作者难以从合法素材走到可试听、可比较、可导出的配音结果；研究者也难以在统一条件下复现或比较不同方法。

同时，视频与声音涉及著作权、肖像权和人格权益。OpenDub 将本地存储、内容哈希、授权参考声音、项目 revision 和运行清单纳入默认流程，避免把“可生成”与“可合法使用”混为一谈。

## 当前已实现的主要功能

截至 `v0.0.1-alpha.0`，以下能力已有源代码和自动化测试支撑：

1. 本地项目、整数微秒时间线和版本冲突控制；
2. 安全的 FFprobe/FFmpeg 媒体探测、字幕解析、音频归一化与确定性渲染基础；
3. 内容寻址的本地素材存储，以及“音频素材 -> 权属声明 -> 参考声音 -> 配音片段”的强制关联；
4. 模型注册表、许可证/权重审计和隔离适配器运行时；全部公开上游后端目前标为 `planned`，未宣称可用；
5. 生成运行清单、候选数据结构、基础时长/静音/削波检查和可恢复本地任务基础；
6. 本地 REST API、CLI 与 Web Studio：可创建项目、导入本地媒体、记录授权、配置片段并在时间线上查看真实项目数据；
7. 用于自动化测试的确定性音频适配器。该适配器只生成测试正弦波，不是用户可用的配音模型。

本阶段尚未声称以下能力已完成：真实视频感知推理、真实情感可控配音后端、稳定声码器适配、完整候选 A/B、真实内容/音色/情感指标、最终 MP4 导出或正式用户案例。

## 技术架构

OpenDub 采用模块化本地单体架构：

1. **项目与时间线层**：版本化 `project.json` 是真相源，SQLite 仅作可重建索引；时间以整数微秒记录。
2. **媒体层**：以参数数组调用 FFprobe/FFmpeg，完成探测、代理、字幕导入、音频处理、配音轨拼接与封装。
3. **授权与素材层**：素材按 SHA-256 内容寻址；参考声音必须关联音频素材和明确权属声明。
4. **模型适配层**：模型以能力合同和固定上游 commit 注册，在隔离子进程中通过 JSON Lines 协议运行。
5. **生成与评测层**：候选、运行清单、随机种子、输入哈希和基础音频/同步指标形成可追溯记录。
6. **交互与服务层**：FastAPI 提供仅本机默认绑定的 API；Typer 提供 CLI；React Web Studio 提供项目与时间线工作台。

## 项目创新点

1. 将视频、台词、授权声音、情感方向和目标时间窗统一为稳定的数据合同，降低研究后端接入和比较成本。
2. 将授权声明、内容哈希、revision 冲突控制和运行清单设计为默认流程，而非事后文档约束。
3. 用“能力声明 + 许可/权重审计 + 真实烟雾测试”控制模型准入，不把论文、网页 Demo 或未核验权重等同于产品能力。
4. 把多模态配音研究成果组织为可替换功能后端，为视觉韵律、情感控制、风格控制和声学渲染建立统一工程入口。

## 社区贡献与技术基础

团队已有 HPMDubbing、StyleDubber、EmoDubber 和 HPMDubbing_Vocoder 等公开视频配音相关研究成果。这些仓库在 OpenDub 中被明确定位为“技术基础和拟适配上游”，而非当前已经内置的后端。申报提交前，应从各项目公开主页实时核验并补充 Stars、Issues、版本发布、论文和贡献者等数据；不要在此文中预写会变化的数字。

OpenDub 新增的社区价值在于：公开统一 Schema、模型能力合同、上游审计记录、可复现运行清单、本地优先的授权工作流及面向开发者的适配入口。

## 兼容与适配情况

当前自动化验证环境为 Linux、Python 3.13、FFmpeg 和现代 Chromium 浏览器。项目元数据声明支持 Python `>=3.11,<3.14`；GPU、CUDA、国产硬件、Docker GPU、真实模型权重和浏览器视频格式尚未完成受控验证，不应写为“已支持”。

## 阶段目标

### M1：可信项目闭环

- 完成统一主仓库、开源治理、项目 Schema、媒体基础、本地授权和 Web Studio 项目设置流程；
- 发布可运行 alpha，公开模型准入边界和测试基础。

### M2：真实模型闭环

- 在权重许可明确、真实烟雾测试通过后接入首个配音后端与声码器；
- 完成候选生成、接受、基础评测、WAV/MP4 渲染与受控 GPU 验证报告；
- 真实验证情感参数对输出的可测影响后，才宣称“情感可控”。

### M3：开源发布与生态建设

- 完成 Docker、CI、两套可再分发示例、中英文文档和 Adapter 教程；
- 发布 `v0.1.0`，建立 Issue、Discussion、外部体验和适配贡献机制；
- 在同样的准入规则下推进 HPMDubbing、StyleDubber 等后端扩展。

## 商业化与可持续计划

核心项目保持开源。项目成熟后可面向内容团队提供可选的私有部署、模型适配、推理优化、生产流程集成和技术支持服务；不以采集用户素材、出售未授权声音或封闭 SaaS 为短期目标。

## 希望获得的孵化支持

1. 受控 GPU 算力和真实模型推理环境，用于完成首个后端和声码器验证；
2. 开源许可证、模型权重和数据合规指导；
3. 内容创作、公开课或数字人等授权场景的试用与反馈；
4. 开发者社区传播、外部 Adapter 共建和国产算力验证资源。
